What does this test verify?Browser-local · not a server login
Registration

Checks the returned origin, RP ID hash and authenticator flags. Saves a local public key; does not validate attestation with a server.

Authentication

Checks the challenge, origin, RP ID hash and assertion signature against the browser-local record. No trusted account session is created.

Physical key context

Shows transports and AAGUID when the browser reports them. It cannot identify a connected device or read CTAP capabilities directly.

For a production relying party, server-side challenge management, registration verification, trusted credential storage and session handling are required. WebAuthn specification ↗

Browser test records
Local test records stored in this browser.
These entries come from this browser only. Discoverable status describes registration evidence, not a live inventory of the card.
Deleting these records does not remove credentials from your security key or smart card, even when the device is connected.


Credentials on your device
Browser records and credentials on a security key or smart card are separate. This website cannot list or remove credentials stored on your authenticator.
Using an HID Crescendo card? Use the free HID Crescendo Manager for supported card-management operations. Check the documentation for your model and the available FIDO credential-management features before making changes.
Crescendo Manager guide ↗ · Download Crescendo Manager ↗
Other FIDO2 security keys and cards: use the manufacturer's supported credential manager or a compatible local CTAP credential-management tool. Some operations require the authenticator PIN; availability depends on the device.
Reset is a last resort. It can erase credentials and, depending on the card and operation, other applications or data. Do not reset a card just to repeat a WebAuthn test. FIDO specifications ↗




Clear browser records?
This only removes browser-local test records. It does not erase any credential from a physical authenticator.




 SECURITY BOUNDARY — This lab verifies a WebAuthn assertion in your browser, but it does not provide trusted RP registration, server-held challenges, attestation verification, account sessions or enterprise device assurance. Local storage is editable. Do not use this as production authentication. Registration is RP-ID bound. Local testing on localhost or 127.0.0.1 and production on edwardcher.online use separate credentials and browser records. WebAuthn reference.

Registration and authentication
Registration calls navigator.credentials.create(); authentication calls navigator.credentials.get(). Run a test to see the exact operation and options.

   
API call · illustrative
await navigator.credentials.create({ publicKey: options });

   
What to look for
  • Challenge: random data that binds the response to the current request.
  • RP ID and origin: credentials are scoped to the relying party.
  • Authenticator selection: browser hints and policy are not physical device detection.

Hardware troubleshooting
  • USB-C: connect a FIDO2 authenticator and complete the browser prompt.
  • NFC: hold a FIDO-enabled card near the phone when prompted, if supported by the platform.
  • Smart cards: PKI/PIV alone is not a FIDO2/WebAuthn authenticator.
  • NotAllowedError can mean cancellation, timeout or other conditions; it does not prove hardware absence.
