Identity / Privacy

How much can a website learn about you without you ever signing in?

Explore browser fingerprinting, device signals, network context and the limits of identity attribution.

We tend to associate identity with signing in. Yet a website can begin learning about a visitor long before an authentication ceremony takes place. The question is not simply whether a website knows your name, but whether it can recognize your browser again and associate observations with earlier activity.

Explore your Browser Footprint to inspect the signals discussed here, including their live values and the APIs used to obtain them.

From observation to recognition

An HTTP request already reveals information to the receiving service, including the apparent source IP address and request headers. JavaScript adds another layer: display dimensions, language preferences, time zone, reported platform and hardware concurrency. Some browsers deliberately reduce or withhold these values to limit fingerprinting.

Individually, these observations are often unremarkable. Their combination can be more distinctive. A fingerprinting implementation normalizes selected values and may hash them into a compact identifier. Hashing does not create additional identifying information, however. Two browsers with identical inputs produce the same hash, while a configuration change can produce a different hash for the same browser.

A first-party cookie offers a different mechanism: recognition of a browser profile that retains a stored value. It does not establish that the same physical device or person has returned. Fingerprinting and cookies should not be confused with one another.

The security value — and the privacy cost

In identity security, device and network observations can provide context for a risk decision. A change in browser characteristics or network location may justify additional verification, especially when combined with other evidence of suspicious activity. But a changed fingerprint is not evidence of compromise on its own. Browser updates, accessibility settings, privacy controls and external displays can all change the observations.

The same ability to correlate visits can also support unwanted tracking. The distinction lies in purpose, consent, retention and how the resulting intelligence is used. A defensive implementation should collect only what it needs, document its limitations and avoid turning uncertain observations into definitive claims about a person.

Beyond the browser

A public IP lookup may reveal an approximate network location, provider and autonomous system. It does not establish a residential address or a person’s identity. VPNs, shared networks and proxies complicate interpretation; their presence is not inherently suspicious. Public-source intelligence can add context, but attribution requires independent corroboration and appropriate authorization. Browser APIs do not reliably reveal whether a VPN or screen-recording application is active.

Recognition is not authentication

A fingerprint is a correlation signal, not a cryptographic credential. A high observation-coverage score says that more requested values were available; it does not measure uniqueness, identity confidence or fraud probability. Establishing statistical uniqueness requires a representative comparison population. Authentication using a passkey, by contrast, can demonstrate possession of a registered cryptographic credential through a challenge-response ceremony.

These distinctions matter when designing risk-based authentication: intelligence can inform a decision, but should not silently replace the evidence needed to establish trust.

A living browser API reference

Browser Footprint makes the collection process visible. Expand each observation to inspect its source expression, raw value and limitations. The particle portrait represents the available signals, not your actual appearance. Local analysis is the default; network lookup and remembering visits are optional.

More advanced backend capabilities are coming soon. The aim is to make the boundary between observation, correlation and verified identity clearer as the tool evolves.
