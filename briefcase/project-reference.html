Briefcase Project Reference

Structure, attributes and conventions of a portable Briefcase project.

Download example project · Generation Guide

Project lifecycle

Open a JSON project, refine the five executive perspectives, and save a portable copy using Project tools. Changes are stored locally in the browser when storage is available. Switching initiatives replaces the active project; export first. Review snapshots are not formal approvals.

Project attributes

The current runtime accepts legacy state or the versioned portable envelope. This is a field reference, not a strict JSON Schema; the existing validator is authoritative.

Defaults vary by initiative. All numeric fields must be finite; years and ramp must be integers.

Portable envelope

schema = edwardcher.intelligence; version = 1; calculationVersion must match the runtime. The exported envelope also contains scenarioVersion, scenarioGuidance, state and evidence. The runtime validates state when unpacking; external evidence references are not verification.

Validation and portability

Run node scripts/briefcase.mjs validate project.json from the extracted project root. The runtime validator is authoritative. Review exported assumptions, notes and evidence before sharing. See the Journey DSL for initiative authoring and the Generation Guide for output workflows.
