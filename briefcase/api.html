Briefcase Generation API

Plain-text API reference · Download reference

Boardroom to Terminal · Strategic thinking. Pragmatic engineering.

01 / PURPOSE

Generate repeatable executive briefs from portable JSON. This is a local JavaScript module contract, not a hosted REST API. No API key is required.

02 / TERMINAL WORKFLOW

From the extracted project root, using Node.js:
  node scripts/briefcase.mjs validate project.json
  node scripts/briefcase.mjs pack project.json > portable.json
  node scripts/briefcase.mjs compose portable.json > presentation.json
  node scripts/briefcase.mjs html portable.json > brief.html
Example inputs: static/briefcase/examples/*.json
The CLI uses the default board audience and Edwardcher theme.

03 / MODULE CONTRACT

static/briefcase/portable.mjs
  pack(state) -> versioned edwardcher.intelligence object
  unpack(project) -> validated state (also accepts legacy state)
static/briefcase/present.mjs
  deck(state, audience=0, theme=false) -> eight-slide presentation model
  preview(model, slideIndex=0) -> HTML fragment
  printHTML(model) -> printable HTML document
  await powerpoint(model, PptxConstructor) -> PowerPoint instance
Audience: 0 board, 1 investment committee, 2 architecture and risk.
Theme: dark (default), light, blue. Boolean true also selects light.
Use the bundled PptxGenJS constructor for browser PowerPoint generation.
Call writeFile on the returned instance to export. PDF uses browser print.

04 / DATA AND TRUST

Portable schema: edwardcher.intelligence, version 1; calculation version must match. Presentation schema: edwardcher.presentation, version 1. USD only. Do not relabel non-USD values. Evidence references are not verification; assumptions and qualitative risk ratings are not approvals. The raw project and presentation model may contain sensitive business data. Review before sharing. Generation is local; no hosted generation endpoint.

Portable envelope

schema = edwardcher.intelligence; version = 1; calculationVersion must match the runtime. The exported envelope also contains scenarioVersion, scenarioGuidance, state and evidence. The runtime validates state when unpacking; external evidence references are not verification.

Presentation style

Use deck(state, audience, theme) to select the narrative and appearance independently. The browser supports dark, light and blue themes. The CLI uses the default board audience and dark theme. Presentation theme fields include id, version, brand, background, foreground, accent and muted. Colour values must be six-digit hexadecimal when rendering. Changing exported PowerPoint does not change the source project.
