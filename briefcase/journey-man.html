03 / Terminal quick start

Prefer a shell? From the extracted project root, with Node.js installed:

node scripts/briefcase.mjs validate static/briefcase/examples/passwordless.json
node scripts/briefcase.mjs pack static/briefcase/examples/passwordless.json > intelligence.json
node scripts/briefcase.mjs compose intelligence.json > presentation.json
node scripts/briefcase.mjs html intelligence.json > presentation.html

These commands work in the current release. The CLI uses the default board template and dark theme; other templates and PowerPoint export are available in the browser. PDF uses browser printing. The current engine accepts only the three built-in scenario identifiers (0, 1, 2).

Unix notes: JSON is the interchange format; redirect output to files, inspect with jq if installed, and keep source inputs under version control. Do not commit confidential data. Generated files are disposable; the inputs are not.

04 / Extend a journey

DeclareDefine the journey
→
ValidateResolve contracts
→
ComposeGenerate blueprint

Create a journey only when the methodology changes. Start with inherited conventions, then declare what is different. This privileged-access example is a language definition example; see the compatibility note for runtime support.

journey privileged-access version 1.0

title "Privileged Access Modernisation"
domain identity
use conventions executive-v1
use model qualitative-risk-v1

objective "Reduce standing privileged access"

perspective ceo
  require objectives, scope, priorities
  derive strategic_mandate

perspective cro
  require risk_register, appetite
  derive residual_risk

dataset risks
  schema risk-register-v1
  accept csv, xls, xlsx, json

presentation board
  template board-decision-v1
  theme edwardcher-dark
  slides 8

Inherit the executive conventions to supply the remaining perspectives and standard layouts. Overrides must be explicit. Register a reviewed financial model appropriate to privileged access before deriving investment metrics; do not assume authentication economics applies unchanged.

05 / Language reference

DirectiveMeaning
journey ID version NStable journey identity and definition version.
title / domain / objectiveHuman-readable purpose and domain.
use conventions IDInherit versioned defaults.
use model IDSelect a registered, reviewed calculation model.
perspective ROLEOverride a role’s required inputs and derived outputs.
require / deriveDeclare field and metric identifiers, not executable expressions.
dataset ID / schema / acceptDeclare an input contract and allowed adapters.
presentation ID / template / theme / slidesSelect a registered narrative, appearance and eight-slide limit.

Lexical conventions: UTF-8, case-sensitive identifiers, quoted strings, two-space indentation for block members, comma-separated identifier lists. Reject unknown directives, duplicate IDs, missing required fields and unresolved references. No arbitrary code, network calls or shell execution. Formal grammar and compatibility policy will accompany the parser.

Each perspective contributes inputs to the same intelligence model.

CIOArchitecture and milestones → target state, roadmap
CISOThreats and controls → security gaps
CROAppetite and treatment → residual risk, acceptance decisions

Bring your own data — planned

CSV and Excel adapters will normalise tabular data into canonical text. Example risk register:

risk_id,likelihood,impact,treatment,owner
R01,3,4,mitigate,Security

Define rating scales, units, currency and time horizon. Retain source, observation date, evidence status and calculation version. Missing data is unknown, not zero. Spreadsheet imports are not yet implemented; the example schema is illustrative.

Never execute macros or formulas during import. Review cached formula results and retain provenance.

07 / Deliver the decision

Choose Board decision, Investment committee or Architecture & risk review. Each uses the same intelligence, with a different narrative sequence. Dark and light themes are available.

Export editable PowerPoint or standalone HTML; use browser printing for PDF. Keep detailed evidence in the dossier. Planned chart and matrix bindings will use canonical datasets, not independently invented figures. Label assumptions and proposed controls; risk acceptance requires explicit approval.

08 / Validate before delivery

ProblemAction
Invalid initiative or versionCheck the source JSON and supported versions.
Invalid cost or controlCorrect the input, units or control reference.
Invalid governanceReview risk ownership, treatment and appetite.
Negative returnReview assumptions; do not force a positive result.

Rerun validation before composing. For future custom journeys, test unique IDs, model compatibility, missing inputs, all five perspectives, eight-slide output and browser/terminal parity. Pin versions and inspect the exported slides.

09 / Trust and portability

Use synthetic data in public examples. Keep credentials, tokens, personal records and restricted evidence out of public repositories. Validate imported sizes, types and references. Store evidence metadata separately from restricted originals.

The Journey DSL is declarative: no shell execution, arbitrary code or network calls. Retain source data and versioned methodology alongside deliverables.
